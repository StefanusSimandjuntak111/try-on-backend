# API Documentation

## Try-On Endpoints

### POST `/api/v1/tryon/direct` - Direct Try-On (Recommended)

Upload both images directly and get the fitted result in one request.

**Input:**
- `model_file` (File, required): Human model image file (person photo)
- `garment_file` (File, required): Clothing/garment image file
- `model_name` (String, optional): Name for the model
- `garment_name` (String, optional): Name for the garment
- `options` (JSON String, optional): Processing options

**Response:**
```json
{
  "id": "job-uuid",
  "model_id": "model-uuid",
  "garment_id": "garment-uuid",
  "result_url": "https://.../result.jpg",  // Final fitted image (when completed)
  "status": "queued|processing|completed|failed",
  "error_message": null,
  "processing_time": null,
  "options": {},
  "created_at": "2024-01-01T00:00:00",
  "completed_at": null
}
```

**Example:**
```bash
curl -X POST "http://localhost:8500/api/v1/tryon/direct" \
  -F "model_file=@person.jpg" \
  -F "garment_file=@shirt.jpg" \
  -F "model_name=Person 1" \
  -F "garment_name=Blue Shirt"
```

### POST `/api/v1/tryon` - Try-On with Existing IDs

Create a try-on job using already uploaded model and garment.

**Input:**
```json
{
  "model_id": "uuid-of-model",
  "garment_id": "uuid-of-garment",
  "options": {
    "size": "M",
    "quality": "high",
    "background": "original"
  }
}
```

**Response:** Same as `/direct` endpoint

**Example:**
```bash
curl -X POST "http://localhost:8500/api/v1/tryon" \
  -H "Content-Type: application/json" \
  -d '{
    "model_id": "123e4567-e89b-12d3-a456-426614174000",
    "garment_id": "123e4567-e89b-12d3-a456-426614174001"
  }'
```

### GET `/api/v1/tryon/{job_id}` - Get Try-On Result

Get the final fitted image result.

**Response:**
```json
{
  "id": "job-uuid",
  "model_id": "model-uuid",
  "garment_id": "garment-uuid",
  "result_url": "https://.../result.jpg",  // Final fitted image URL
  "status": "completed",
  "error_message": null,
  "processing_time": 45.2,
  "options": {},
  "created_at": "2024-01-01T00:00:00",
  "completed_at": "2024-01-01T00:00:45"
}
```

**Important:** 
- The `result_url` contains the **final fitted image** showing the clothing on the model
- This URL is a presigned URL valid for 1 hour
- Download or use this URL to display the result

### GET `/api/v1/tryon/{job_id}/status` - Get Job Status

Check the processing status of a try-on job.

**Response:**
```json
{
  "id": "job-uuid",
  "status": "queued|processing|completed|failed",
  "error_message": null,
  "estimated_time": 30,
  "progress": 75.0,
  "created_at": "2024-01-01T00:00:00",
  "completed_at": null
}
```

## Model Upload Endpoints

### POST `/api/v1/models/upload` - Upload Human Model Image

Upload a human model image for try-on.

**Input:**
- `file` (File, required): Human model image (person photo)
- `name` (String, optional): Model name
- `metadata` (JSON String, optional): Additional metadata

**Response:**
```json
{
  "id": "model-uuid",
  "name": "Person 1",
  "image_url": "https://.../model.jpg",
  "thumbnail_url": "https://.../model_thumb.jpg",
  "status": "processing",
  "created_at": "2024-01-01T00:00:00"
}
```

## Workflow Summary

### Option 1: Direct Upload (Simplest)
1. POST `/api/v1/tryon/direct` with both image files
2. GET `/api/v1/tryon/{job_id}` to get the result
3. Use `result_url` to download/display the fitted image

### Option 2: Separate Upload (Reusable)
1. POST `/api/v1/models/upload` → Get `model_id`
2. POST `/api/v1/garments/upload` → Get `garment_id`
3. POST `/api/v1/tryon` with both IDs → Get `job_id`
4. GET `/api/v1/tryon/{job_id}` to get the result
5. Use `result_url` to download/display the fitted image

## Result Image

The `result_url` in the response points to the **final fitted image**:
- Shows the clothing/garment fitted on the human model
- Generated by the HR-VITON model
- Format: JPEG or PNG
- Accessible via presigned URL (valid for 1 hour)

## Status Values

- `queued`: Job is waiting to be processed
- `processing`: Job is currently being processed
- `completed`: Job completed successfully, result available
- `failed`: Job failed, check `error_message`

## Error Handling

All endpoints return appropriate HTTP status codes:
- `200`: Success
- `201`: Created
- `202`: Accepted (async job created)
- `400`: Bad Request (validation error)
- `404`: Not Found (resource not found)
- `500`: Internal Server Error

Error responses include:
```json
{
  "error": "ErrorType",
  "detail": "Error message",
  "path": "/api/v1/tryon/..."
}
```
